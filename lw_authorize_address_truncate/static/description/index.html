Authorize.Net Address Truncate

Fixes Silent Payment Failures

Authorize.Net hard-rejects billTo blocks over its XML schema limits (address 60, city 40, zip 20 chars) before the card is ever attempted — this module removes that failure mode.

Clamps at the Right Hook

Overrides _get_specific_create_values() so clamping survives core’s partner-derived value population, instead of being silently overwritten.

Minimal Intervention

Only values over the limit are hard-sliced and right-stripped; in-range values are left completely untouched.

Provider-Scoped

Applies only to the authorize provider — other providers keep standard behavior.

How it works

  1. Install the module — it activates automatically for the Authorize.Net provider.
  2. When a transaction is created, any partner address, city, or zip over the gateway limit is sliced to the limit and right-stripped.
  3. In-range values pass through unchanged.
  4. Customers no longer hit unexplained payment failures from long addresses.

Frequently asked questions

How do I install and configure the module?

Install it like any Odoo module (Apps > Update Apps List, then Install). It requires the standard payment_authorize module and needs no configuration — the clamping applies automatically to every Authorize.Net transaction.

Which Odoo versions does it support?

This module is built for Odoo 19.0 (module version 19.0.1.0.0) and is live-tested on Odoo 19 Community Edition.

What if the module doesn't work as expected?

This module is free on the store. Paid apps on the Odoo Apps Store are covered by the store's refund policy: buyers may request a refund within 14 days of purchase if the app does not work as described.

How fast is support?

Questions get a reply within one business day at stephen@loomworks.dev.

Is my data safe?

Yes. The module runs entirely inside your own Odoo database and collects nothing. It adds no external calls beyond the Authorize.Net transactions your Odoo already makes.

Will it change addresses that are within the limits?

No. Only address, city, or zip values over the Authorize.Net schema limits are clamped. Everything already within the limits passes through byte-for-byte unchanged.
